Stage 4 — Architecture Diagram. Rendered from docs/architecture/architecture.md (Stage 3, Architecture Council, reconciled 2026-09-12) and docs/architecture/threat-model.md (2026-09-12), plus ADR-0001, ADR-0002, ADR-0003. This diagram visualizes the approved topology; it does not revise it. If this file's revision date is older than the source documents, re-render before relying on it.

Text summary of topology: Josh's browser sends HTTPS requests with a bearer token to the Web app frontend. The frontend makes a same-origin API call, also carrying the bearer token, to the Backend API layer (serverless functions). The Backend API verifies the bearer token on every route, then reads the version-controlled curated metadata file (build-bundled, not network-crossing) and issues a single batched GraphQL query to GitHub.com using a fine-grained, read-only Personal Access Token, scoped to about 27 repositories (ADR-0001, ADR-0003). GitHub is read-only; there is no write path back to GitHub. Separately, Josh manually syncs the GitHub PAT and the dashboard bearer token from Phase.dev, the trusted secret broker, into the deployment platform's (Vercel or Cloudflare) environment-variable store at deploy time; the running app reads secrets from that platform env store, not from Phase.dev at request time. Preview deployments, created automatically per pull request by both candidate platforms, must not receive these production secrets (ADR-0002) — implementation must either supply empty/dummy preview env vars or disable preview deployments outright. The only untrusted actor in this model is an anonymous internet caller with no valid bearer token.

GitHub Portfolio Status Dashboard — Architecture Topology

Single-user, read-only, on-demand-refresh dashboard. Tier: load-bearing. Stage 3 (Architecture Council) reconciled 2026-09-12 — see architecture.md and threat-model.md.

Untrusted network
Browser (Josh only) Trusted human, untrusted network path. Sole intended user — single shared bearer token, no accounts/OAuth.
Anonymous caller Realistic adversary in this model. No valid bearer token = no data (threat-model.md §1).
Deployment platform (Vercel or Cloudflare) Preview deploys: no prod secrets — ADR-0002
Web app (frontend) Static/SSR portfolio page. No GitHub PAT ever reaches client-side code.
Backend API layer Serverless functions. Sole holder of the GitHub PAT. Verifies bearer token on every route. Merges GitHub + curated metadata.
Curated metadata file Git-tracked (e.g. portfolio-metadata.json), build-bundled. Deploy-time-frozen, not live. Tolerant parse per-entry, fail-closed if fully malformed.
Env var store (runtime secret copy)
GitHub PAT Fine-grained, read-only, ~27-repo scoped (ADR-0001). Server-side only.
Bearer token Sole dashboard access gate. No rotation/expiry — accepted risk (threat-model.md §6).
External API
GitHub.com ~27 repos. Sole source of operational truth (PRs, issues, activity). Never mutated — no write path (ADR-0003 batched GraphQL, read-only).
Secret broker
Phase.dev System of record for both secrets. Trusted secret broker (project-wide policy). Josh syncs manually at deploy time.
Josh (operator) Manually syncs secrets Phase.dev → platform; edits metadata via commit + deploy.
